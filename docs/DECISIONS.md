## 2026-09-15 - launch audit fixes (titles, meta, headings, images, headers)

- 2026-09-15 | The brand suffix on blog <title> tags is now conditional (`withBrand` in src/lib/seoTitle.ts): appended only when the whole title fits in 60 characters, dropped otherwise. | 71 of 97 post titles were over 60 WITH the suffix but only 29 were over on their own. The suffix costs 21 characters on the LWS blog and 24 on Live Band, so it, not the headlines, was the cause on 42 posts. The brand is already in the domain shown above the title, so losing it beats truncating the headline that explains the page.
- 2026-09-15 | New optional `seoTitle:` frontmatter field, set on the 29 posts whose headline is over 60 by itself. | Jon wrote every headline and wants them kept ("i wrote everything....all mine"). This lets the <title> be short for the search result while the H1 on the page stays the headline as written. Verified on three posts: title 48-55 chars, H1 unchanged.
- 2026-09-15 | Image width/height are READ FROM THE FILE at build time (src/lib/imageSize.ts), not hand-typed. | 139 images were missing them. Hand-typing 139 pairs is 139 chances to be wrong, and a wrong pair is worse than none: it reserves the wrong box, so the shift still happens AND the image renders distorted. The parser was checked against macOS `sips` on all 309 images in public/images: 309 matches, 0 mismatches.
- 2026-09-15 | PhotoBg reads its own dimensions rather than taking them from the caller. | The props existed already and nine of ten callers simply omitted them, which is how eight bluestage heroes shipped with no aspect ratio. A component that reads the file cannot be forgotten.
- 2026-09-15 | The Footer carries its own `<h2 class="visually-hidden">Site navigation</h2>`. | The 2026-09-14 pass moved the footer columns h4 -> h3, which fixed the 72 pages whose last body heading is an h2 but left every THIN page broken (thank-you, newsletter, forms: no body h2 at all, so h1 -> h3). Anchoring the level inside the footer fixes it for any page, including ones not written yet. Cleared 4 of the 15 skips on its own.
- 2026-09-15 | The card-grid pages got `visually-hidden` h2s rather than new visible section headings. | 10 pages needed a heading between the h1 and the card h3s. A visible one means writing new copy onto seven service pages without Jon seeing it. Hidden is a structural fix, not a copy change. On /services the label also CANNOT be the visible pill: `.sec-head h2` in global.css is more specific than `.eyebrow--tag`, so the pill would have blown up to a 3rem title. Verified the pill still computes to 12.8px.
- 2026-09-15 | contact.astro's "Talk to Jon." went h3 -> h2 and its three style selectors widened to `:is(h2,h3)`. | It is the only heading between that page's h1 and the footer, so it was a genuine skip. Widening the selectors rather than switching them means the rules cannot silently stop applying, and a future h3 under it still gets the treatment. `:is()` takes its most specific argument, so specificity is unchanged.
- 2026-09-15 | verifiedsecured.png renders at opacity 1. | Jon: "the verifiedsecured.png is dark". Two rules dimmed it, `.badge img{opacity:.6}` in mosa-skin.css winning over `.85` in global.css. The file has NO alpha channel, so any opacity under 1 blends the dark footer through the white plate and greys the whole badge.
- 2026-09-15 | HSTS ships WITHOUT `includeSubDomains` and without `preload`. | The apex and www are on Netlify and always HTTPS, but a subdomain on another host (webmail, cPanel, staging) would become unreachable in every browser that had seen the header, curable only by waiting out the max-age. `preload` is a one-way door needing a removal request. Both are one-line additions once every subdomain is confirmed HTTPS.
- 2026-09-15 | No Content-Security-Policy in netlify.toml. | The site loads Google Analytics, Mailchimp, Formspree and Netlify Identity. A CSP written blind would break a form or the CMS login silently. That one wants its own pass with the network tab open.
- 2026-09-15 | `rel=preload` is emitted only for PHOTO heroes (46 pages), never for the video or shader heroes. | There is no single image to prioritise on a VideoBg page, and preloading video bytes competes with the text for bandwidth. The preload href is built from the same relPrefix() call as PhotoBg's src so the two cannot drift: a href differing by one "../" downloads the hero twice. Verified 0 mismatches across 46 pages, and one network request for the hero on a live page load.
- 2026-09-15 | The lightbox <img> on /services/custom-styles-and-carousel-cards keeps NO width/height. | It is the only image left without them. Its src is set by JS from the full-size href, which is a different file from the thumbnail, so any dimensions would be a guess. It is also a user-opened overlay, and CLS excludes shifts within 500ms of user input, so it contributes nothing to the metric. Wrong numbers would be worse than none.
- 2026-09-15 | Four blog slugs renamed, not redirected. | `3-23-pm-google-changed-...` leaked a WordPress export timestamp; three others ran 68-87 characters. Checked first that no rule in public/_redirects targets a specific post (they all land on /blog) and that nothing in src or public links to them, so there is nothing to redirect from. v3 has not shipped, so these URLs have never been live.
- 2026-09-15 | NOT DONE, needs Jon: the 42 restored WordPress posts are all `draft: true` and render nowhere. 67 business posts exist, 25 build. Flagged rather than flipped: publishing 42 articles is an editorial call.
- 2026-09-15 | NOT DONE, needs Jon: specs/qa-checklist.md line 22 says the footer badge is "native 168x56" and must never be a fixed 150x37. The asset on disk IS 150x37 (verified with sips) since the 2026-08-27 swap, so the checklist is stale and the current markup is correct.

## 2026-09-14 - Namesake Session 1

- 2026-09-14 | Island root is `display: contents` so one mount point supplies two grid items (`.nsp-controls` under the headline on the left, `.nsp-stage` spanning both rows on the right). | The handoff wants the card and the preview in different hero columns, which would otherwise need two islands and a shared store for one piece of state.
- 2026-09-14 | The hero grid places those two with DESCENDANT selectors, not child selectors. | `display: contents` removes `.nsp-root`'s box from layout but leaves it in the DOM tree, so it is still the direct child and `>` matches nothing. Written with `>` the rules silently no-op and all three items auto-place into the wrong cells. Cost one debugging round; noted here so it is not reintroduced.
- 2026-09-14 | Name font size is four bands per style on `data-nsp-len`, measured from the LONGEST RENDERED LINE rather than the whole string. | bold and warm set a name on two lines, so "Maximilian Featherstonehaugh III" must size off "Featherstonehaugh III" (21) and not 32. Verified across 4 styles x 4 names: zero text overflow.
- 2026-09-14 | The bold marquee derives its repeat count from name length instead of using a fixed one. | A fixed 8 repeats cannot do both jobs: it covers only 620 of the 1440 for "Al" (row reads half empty) and builds 5292px of clipped layout for a 32-character name. Now 3 to 19 repeats, every name covering the full width.
- 2026-09-14 | `.nsp-page` sets its own `text-align` and the four page bodies are `height: 100%`. | The live frame is a `<button>`, which the UA stylesheet centres, and the body elements were auto-height so their `flex: 1` middles had no free space to absorb. Both had to be fixed for the three renders (frame, modal, export host) to agree, which Session 2 depends on.
- 2026-09-14 | Scale is written as `--nsp-scale` through `element.style.setProperty`, the island's only style attribute. | Container width over 1440 is a runtime number that cannot live in a stylesheet. Passing it as a custom property keeps the CSS owning what it is used for. Frame height is reserved by `aspect-ratio: 16/10` rather than a measured pixel height, so nothing shifts before the fonts resolve.
- 2026-09-14 | Chip swatches and per-chip display faces are CSS rules keyed off `data-style`, not inline custom properties. | Keeps the no-inline-styles rule intact with 12 swatches and 4 type samples.

## 2026-09-14 - Namesake Session 2

- 2026-09-14 | The ten faces are registered TWICE: through the FontFace API (rendering, URL from `base`) and through a runtime `<style>` element carrying the same `@font-face` rules. | Session 2D of the handoff predicted this and it is real, not precautionary. html-to-image builds its embedded font CSS by walking `document.styleSheets`; FontFace-API faces are not in there. Measured on the bold style: the name's ink is 854px wide in the PNG with the style tag and 940px without it, against 868px on screen. Without the tag the PNG ships a fallback face. Same URLs, so the browser serves both from one fetch.
- 2026-09-14 | `.nsp-modal` restates `margin: auto`. | A `<dialog>` centres itself with the UA's `margin: auto`, and global.css line 57 resets every element to `margin: 0`, which took that with it and pinned the modal to the top left corner.

- 2026-09-14 | Escape is closed by an explicit `keydown` handler on the dialog rather than relying on the browser's native `cancel`. | Verified in this environment that the Escape keydown reaches the document while the dialog's `cancel` never fires, so the native path alone left the modal undismissable from the keyboard. Closing an already closed dialog is a no-op, so this is safe alongside the native behaviour.
- 2026-09-14 | The export host renders only while the modal is open. | It is a full unscaled 1440x900 subtree; there is no reason to carry it in the DOM for every visitor who never opens the modal.
- 2026-09-14 | The four reference PNGs ARE on disk, in the session scratchpad under namesake-pngs/. | The Browser pane's sandbox discards downloads (confirmed by a full home-directory scan: no file anywhere), so the page posted each blob to a throwaway Node receiver on 127.0.0.1:4399 instead. The classical export was opened and read back: genuine Libre Caslon Display and Lora italic, not a fallback.
